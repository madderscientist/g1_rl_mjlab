# 下肢行走任务配置说明

本文档描述任务 `G1-Gloria-LowerBody-Flat` 的**当前生效配置**。基础配置按 manager 拆在
[cfg/](cfg/) 下（`cfg/env_cfg.py` 负责组装，G1 + 双 Gloria-M 的机器人专属覆盖也在那里），
PPO 配置在 [rl_cfg.py](rl_cfg.py)。奖励和事件的具体实现见 [mdp/](mdp/)，
课程档位表在 [cfg/constants.py](cfg/constants.py)。

策略控制 12 个腿关节和 3 个腰关节，跟随四个上层指令
`[前进速度 vx, 侧移速度 vy, 转向角速度 ω, 骨盆离地高度 h]`。手臂不在动作空间中，由位置执行器保持目标姿态，并通过随机目标、关节力矩和机身冲量模拟上层手臂策略带来的扰动。

## 0. 启动
```bash
eval "$(micromamba shell hook -s bash)"
micromamba activate mj

# GPU 0（默认；列表字面量必须加引号）
python scripts/train.py G1-Gloria-LowerBody-Flat --env.scene.num-envs=4096 --gpu-ids '[0]' --mirror-schedule '()'

# GPU 1
python scripts/train.py G1-Gloria-LowerBody-Flat --env.scene.num-envs=4096 --gpu-ids '[1]' --mirror-schedule '()'

# 指定多张 GPU，或使用全部可见 GPU
python scripts/train.py G1-Gloria-LowerBody-Flat --env.scene.num-envs=2048 --gpu-ids '[0,1]' --mirror-schedule '()'
python scripts/train.py G1-Gloria-LowerBody-Flat --env.scene.num-envs=2048 --gpu-ids all --mirror-schedule '()'

# 当前推荐：关闭 DUP
setsid nohup python scripts/train.py G1-Gloria-LowerBody-Flat \
  --env.scene.num-envs=4096 --agent.max-iterations=15000 \
  --mirror-schedule '()' --gpu-ids '[0]' --agent.run-name=nodup \
  > logs/train_nodup.log 2>&1 < /dev/null & disown

# 仅用于 DUP 对照；不传 --mirror-schedule 时默认读取 MIRROR_STAGES
setsid nohup python scripts/train.py G1-Gloria-LowerBody-Flat \
  --env.scene.num-envs=4096 --agent.max-iterations=15000 \
  --gpu-ids '[0]' --agent.run-name=dup \
  > logs/train_dup.log 2>&1 < /dev/null & disown
```

多卡训练会在每张 GPU 上各启动一个 worker，`--env.scene.num-envs` 是**每张卡**的环境数。
上面的双卡命令每卡运行 2048 个环境，全局共 4096 个。带闸门的课程会把各卡的合格数和
样本数做一次全局 `all_reduce`，因此所有 worker 使用相同的 EMA 分数和课程档位；日志与
checkpoint 仍只由 rank 0 写入，但保存的是各卡已经同步后的状态。

> **DUP 实测为负收益，当前应关闭。** 同配置训练 15000 迭代，`dup` 对比 `nodup`：
> yaw 误差 4.00 vs 3.38，线速度误差 1.85 vs 1.64；手臂前举并带 2 kg 时，vx 达成率 7% vs 125%。转弯不对称虽从 13%/10% 降到 8%/5%，差异落在单次回放噪声内。
> DUP 还使每个 mini-batch 翻倍，训练慢约 15%。
> 左右破缺在训练够久之后**两边都会自行收敛**

续训时 `max-iterations` 是追加量。`common_step_counter` 会恢复环境课程和镜像档位。

```bash
python scripts/train.py G1-Gloria-LowerBody-Flat \
  --env.scene.num-envs=4096 --agent.max-iterations=5000 --agent.resume=True \
  --agent.load-run=<run-name> --agent.load-checkpoint=model_3000.pt \
  --agent.run-name=continued
```

镜像课程可用 Python 字面量覆盖，例如 `--mirror-schedule '((0,0.0),(800,0.2))'`；`'()'` 表示关闭。

> 训练之外的脚本导入 mjlab 前必须 `export LD_LIBRARY_PATH="$CONDA_PREFIX/lib:$LD_LIBRARY_PATH"`，
> 否则会在 sqlite3/IPython/mediapy 那条链上报 `libstdc++.so.6: version CXXABI_1.3.15 not found`。

## 1. 仿真与策略接口

- 地形：平面。
- MuJoCo 物理步长：`0.005 s`，即 200 Hz。
- 动作降采样：4，所以策略控制周期是 `0.02 s`，即 50 Hz。
- episode：`20 s`，最多 1000 个控制步。
- 物理参数：`iterations=10`、`ls_iterations=20`、`ccd_iterations=50`、`njmax=300`、`nconmax=None`。

### Actor 观测

Actor 观测按下表顺序拼接，共 57 维。顺序是部署契约的一部分。

| 顺序 | 项 | 维数 | 噪声与延时 |
|---:|---|---:|---|
| 1 | `base_ang_vel` | 3 | 高斯 `std=0.115`，每局偏置 `std=0.03`，0--2 拍延时 |
| 2 | `projected_gravity` | 3 | 高斯 `std=0.029`，每局偏置 `std=0.01`，0--2 拍延时 |
| 3 | `command_twist` | 3 | `[vx, vy, omega]` |
| 4 | `command_height` | 1 | 骨盆相对最低足底的目标高度 |
| 5 | `phase` | 2 | 周期 0.6 s 的 `[sin, cos]`；近零速度指令时置零 |
| 6 | `joint_pos` | 15 | 相对默认位姿，高斯 `std=0.006`，0--2 拍延时 |
| 7 | `joint_vel` | 15 | 高斯 `std=0.87`，0--2 拍延时 |
| 8 | `actions` | 15 | 上一拍策略动作 |

延时项的 `delay_hold_prob=0.98`，所以延时主要在 episode 内缓慢变化，而不是每拍重采。
最大 2 拍对应 40 ms。Actor 开启 corruption，历史长度为 1。

Critic 先包含同一组观测，再追加 `base_lin_vel`、`base_height`、14 个手臂关节的位置和速度、
双脚高度、腾空时间、接触状态及接触力。Critic 不加噪声，也不加延时。

### 动作

动作是相对默认关节角的位置目标。关节顺序是左腿 6 个、右腿 6 个、
`waist_yaw/roll/pitch`，与真机电机索引 0--14 一致。

| 关节模式 | 每单位动作的目标角缩放（rad） |
|---|---:|
| hip pitch / hip yaw | 0.547546 |
| hip roll / knee | 0.350661 |
| ankle pitch / ankle roll | 0.438577 |
| waist yaw | 0.547546 |
| waist roll / waist pitch | 0.438577 |

## 2. 指令

速度和高度目标都每 3--8 s 重采一次。

### 速度指令 `twist`

- `vx/vy` 在两次重采之间按 OU 过程连续漂移，稳态标准差 `0.2 m/s`，相关时间 `2.0 s`。
- `omega` 是直接角速度指令，不使用 heading controller；`rel_heading_envs=0.0`。
- 10% 环境是精确零速度的站立场景。
- 10% 环境被设为原地转弯，即 `vx=vy=0`。
- 15% 非原地转弯环境被强制直行，即 `omega=0`。
- 高度指令与速度指令独立，因此站立环境也会训练原地蹲起。

速度量程由课程切换：

| PPO 迭代 | `vx` (m/s) | `vy` (m/s) | `omega` (rad/s) |
|---:|---:|---:|---:|
| 0 | `[-0.5, 1.0]` | `[-0.4, 0.4]` | `[-0.8, 0.8]` |
| 1850 | `[-0.9, 1.2]` | `[-0.6, 0.6]` | `[-1.1, 1.1]` |
| 2850 | `[-1.2, 1.5]` | `[-0.8, 0.8]` | `[-pi/2, pi/2]` |

`vx` 上界取 1.5 而不是更高，理由是走跑转换：Froude 数 $Fr=v^2/(gL)\approx 0.5$ 对应人的
2.0--2.1 m/s，代入 G1 腿长 0.79 m 得 1.97 m/s——也就是说 2.0 m/s 已是它**走路**的理论上限，
而 `foot_gait` 的 56% 支撑相位结构上就禁止腾空期。实测一致：没有任何一版策略超过过 1.1 m/s。
量程开到 2.0 等于把 28% 的指令放进一个永远够不着的区间，而那一段对行为没有梯度。
详见第 9 节“环境与课程”。

### 高度指令 `height`

高度是骨盆原点相对两只足底中较低者的距离。第一次采样直接设置为目标；后续目标变化以
`0.15 m/s` 的最大速度发布，避免高度阶跃。

| PPO 迭代 | 采样量程 (m) |
|---:|---:|
| 0 | `[0.70, 0.77]` |
| 1300 | `[0.65, 0.80]` |
| 3050 | `[0.50, 0.80]` |

上界 `0.80 m` 略高于完全直腿时约 `0.7919 m` 的运动学上限，目的是让高指令下的最优行为
始终是尽量站高、伸直膝盖。

## 3. 奖励

每个控制拍的奖励为

$$
r_t = 0.02 \sum_i w_i f_i.
$$

表中的“权重”是配置值，Reward Manager 还会乘控制周期 `dt=0.02 s`。

奖励门限“要求运动”统一使用 $\lVert(v_x,v_y)\rVert_2 + |\omega| > 0.1$。

**指数型奖励** `exp(−误差²/std²)`：std 决定"多大的误差还算可接受"。

### 跟随与位置

| 项 | 权重 | 当前定义 |
|---|---:|---|
| `track_linear_velocity` | +2.5 | $\exp[-(\lVert v^{cmd}_{xy}-v_{xy}\rVert^2+1.5v_z^2)/\sigma_v^2]$，$\sigma_v$ 见下 |
| `track_angular_velocity` | +0.5 | $\exp[-((\omega^{cmd}-\omega)^2+0.05\lVert\omega_{xy}\rVert^2)/0.7^2]$ |
| `track_angular_velocity_avg` | +1.5 | 用本次指令重采以来的平均 yaw 率跟随 `omega`，`std=0.5`；只在要求运动时开启 |
| `stationary_drift` | -0.5 | 站立或原地转弯时，罚相对本次指令起点的位移：$1-\exp(-d^2/0.2^2)$ |
| `velocity_shortfall` | -0.08 | 沿水平指令方向的速度不足；目标为**指令的 0.5 倍**，只罚不足，不罚超速 |
| `track_base_height` | +0.8 | $\exp[-(h^{cmd}-h)^2/\sigma_h^2]$，$\sigma_h$ 由课程从 0.08 收紧到 0.05 |
| `straight_knee` | +0.5 | 静止且高度指令不低于 `0.78 m` 时，奖励 $\exp[-\operatorname{mean}(q_{knee}^2)/0.5^2]$ |

`track_angular_velocity` 管瞬时 yaw 率振荡，`track_angular_velocity_avg` 管直流跟踪。
强制直行环境的目标 `omega=0`，所以平均项也会压制累计航向漂移。

**`track_linear_velocity` 的核宽随指令幅值放宽。** 拐点以下不变，以上线性抬升：

$$
\sigma_v=\sqrt{0.2}\,\bigl[1+\max(0,\ \lVert v^{cmd}_{xy}\rVert-0.8)\bigr].
$$

固定核宽的问题是：指令一超过约 $2\sigma_v$，“站着不动”与“尽力走”的奖励都是数值零，
这一项对行为完全没有梯度，而走路要付的动作/打滑/加速度代价照收不误，于是“大指令就别动”
成为最优解。拐点取 $2\sigma_v$ 附近而不是 0，是为了不损失低速精度（那是“蹭地走”的防线）。
以实测可达速度为准，“站着”与“走到位”的单拍奖励落差（走路净成本实测约 0.6/拍）：

| 指令 (m/s) | 0.5 | 1.0 | 1.2 | 1.5 |
|---:|---:|---:|---:|---:|
| 固定核宽 | 1.71 | 1.77 | 1.40 | **0.55** |
| 当前（带拐点） | 1.71 | 1.90 | 1.80 | **1.43** |

`velocity_shortfall` 的原始值为

$$
\max\left(0,\ 0.5\lVert v^{cmd}_{xy}\rVert-
v_{xy}\cdot\frac{v^{cmd}_{xy}}{\lVert v^{cmd}_{xy}\rVert}\right).
$$

目标取**指令的固定比例**而不是固定值：固定封顶下，指令 0.6 和指令 2.0 站着不动挨的罚
一模一样，而指数核的死区恰恰只在大指令处，压力加错了地方。改成正比后压力随指令线性
增长，且不需要读量程、不需要跟着课程走。与旧的固定封顶 `0.6` 在指令 1.2 处相交，
低速段更轻、高速段更重，单拍峰值仅从 0.048 抬到 0.060（占 `track_linear_velocity`
满值 2.5 的 2.4%），因此权重保持 -0.08。

它只负责把策略推出指数核在大误差处的平坦区；精确跟踪仍由
`track_linear_velocity` 负责。

### 姿态

| 项 | 权重 | 当前定义 |
|---|---:|---|
| `body_orientation_l2` | -1.0 | 躯干 `torso_link` 的重力水平投影平方，即相对竖直倾角的 $\sin^2\theta$ |
| `pelvis_backward_lean` | -2.0 | 骨盆前后倾；后仰死区 4 度、前倾死区 6 度，前倾侧成本乘 0.2 |
| `waist_deviation` | -1.0 | 腰 yaw/roll/pitch 相对默认角的平方和，逐关节系数为 `0.4/0.85/1.0` |
| `hip_yaw_still` | -5.0 | 仅在不要求运动时，把左右 hip yaw 拉回默认角（防内外八） |
| `pose` | +0.5 | 6 个侧向腿关节的可变宽度指数奖励 |
| `body_ang_vel` | -0.05 | 躯干 roll/pitch 角速度平方和，不罚 yaw 角速度 |

令 `g_x` 为重力方向在骨盆坐标系中的 x 分量，`g_x>0` 表示前倾，则
`pelvis_backward_lean` 的原始成本为

$$
\max(0,-g_x-\sin 4^\circ)^2 +
0.2\max(0,g_x-\sin 6^\circ)^2.
$$

两侧死区必须分开给。它是整套奖励里**唯一前后不对称**的项，共用 4 度时等于只向前进需要的
姿态收费：实测能前进的策略骨盆前倾随速度递增（`vx=0.2` 时 -4.4 度，`vx=2.0` 时 +14.7 度；
已部署那版全程 +6~9 度），而前进能力崩掉的策略骨盆全程停在 -1~-4.3 度，恰好贴着
后仰侧免费额度的边。

`pose` 只作用于左右 hip roll、hip yaw 和 ankle roll。其形式为
$\exp[-\operatorname{mean}((\Delta q/\sigma)^2)]$，宽度随指令强度变化：

| 指令强度 | hip roll | hip yaw | ankle roll |
|---|---:|---:|---:|
| `< 0.1` | 0.10 | 0.10 | 0.10 |
| `[0.1, 1.5)` | 0.35 | 0.30 | 0.20 |
| `>= 1.5` | 0.50 | 0.40 | 0.25 |

hip pitch、knee 和 ankle pitch 不在 `pose` 中，因为它们要承担蹲起和矢状面步态。

### 步态

| 项 | 权重 | 当前定义 |
|---|---:|---|
| `foot_air_time` | +3.0 | 只在单脚支撑时奖励模式持续时间接近 `0.4 s`；最大原始值为 0.4 |
| `foot_gait` | +0.5 | 0.6 s 周期，左右相差半周期，前 56% 为支撑相位 |
| `foot_clearance` | -1.0 | 摆动脚相对较低足底的目标高度为 `0.10 m`，按脚水平速度加权 |
| `foot_slip` | -2.0 | 接触脚水平速度平方和 |
| `soft_landing` | -0.002 | 只在刚触地的一拍计算接触力模长 |
| `stand_still_feet` | -0.5 | 不要求运动时，按腾空脚数量收费 |

除 `stand_still_feet` 外，这组奖励只在要求运动时开启。步态相位起点每个 episode 独立采样
`U[0,1)`，Actor 的 `phase` 与 `foot_gait` 使用同一个偏移。

### 平滑、安全与终止成本

| 项 | 权重 | 当前定义 |
|---|---:|---|
| `action_rate_l2` | -0.02 | 15 维策略原始动作相邻两拍之差的平方和 |
| `joint_acc_l2` | -2.5e-7 | 15 个受控关节的实测角加速度平方和 |
| `self_collisions` | -2.0 | 左腿碰撞几何体与右腿子树接触力超过 10 N 的物理子步数 |
| `is_terminated` | -120.0 | 非超时终止时取 1 |

`self_collisions` 由 G1 Gloria 专属配置追加。传感器只统计左腿与右腿之间的接触，手臂碰撞
不反馈给下肢策略；4 个物理子步全部碰撞时原始值为 4。

## 4. 事件与域随机化

### 每个 episode

每个环境先由 `disturbance_level` 事件采一个共享扰动系数 $U(0,1)$。根状态难度、关节初速度、
手臂目标漂移、手臂力矩和机身冲量都乘这个系数，因此同一批环境中始终同时存在安静和高强度
episode。

| 事件 | 当前行为 |
|---|---|
| `reset_base` | yaw 始终在 `[-pi,pi]`；roll/pitch 最大 `±0.35 rad`；线速度最大 `±0.6/±0.6/±0.3 m/s`；角速度最大 `±0.8 rad/s` |
| `reset_robot_joints` | 15 个受控关节角始终随机 `±0.15 rad`；关节初速度最大 `±0.5 rad/s`，初速度受课程和扰动系数缩放 |
| `gait_phase` | 相位偏移重采为 `U[0,1)` |
| `reset_arm_pose` | 在 G1 Gloria 手臂目标范围内采样，并把手臂状态直接写到该目标 |

`reset_base` 中 yaw 不受难度缩放；roll/pitch 和所有根速度才受缩放。关节位置扰动也不缩放，
只有关节初速度受 `reset_joint_vel_level` 控制。

### Episode 内扰动

| 事件 | 时间与幅值 |
|---|---|
| `arm_pose_drift` | 每 1--4 s 重采手臂 PD 目标，blend 由课程控制 |
| `arm_torque` | 14 个手臂关节施加随机力矩 0.2--0.6 s，随后冷却 1.0--3.0 s |
| `body_impulse` | 对双夹爪基座和躯干施加外力/力矩 0.1--0.4 s，冷却 1.5--4.0 s，作用点高于质心 0.1 m |
| `push_robot` | 每 5--6 s 直接叠加根速度：线速度 `±0.5/±0.5/±0.4 m/s`，角速度 `±0.52/±0.52/±0.78 rad/s` |

`push_robot` 不走扰动课程，训练时始终开启；play 配置会删除它。

### Startup 随机化

这些事件在环境创建时采样，不是每个 episode 重采：

| 事件 | 范围 |
|---|---|
| `payload_mass` | 每个夹爪基座增加 `0--2 kg` |
| `foot_friction_left` / `foot_friction_right` | 每只脚独立采摩擦系数 `0.3--1.6`；同一只脚的 7 个足底几何体共享采样值 |
| `encoder_bias` | 所有关节编码器偏置 `±0.015 rad` |
| `base_com` | `torso_link` 质心 x/y/z 各偏移 `±0.05 m` |

## 5. 课程

环境课程里的 `step` 是环境控制步。PPO 每次迭代每个环境采 24 步，因此配置用
`step = PPO迭代数 * 24`。

当前注册的 8 条课程是 `command_vel`、`command_height`、`height_std`、
`reset_pose_level`、`reset_joint_vel_level`、`arm_torque_level`、
`body_impulse_level` 和 `arm_drift_level`。

### 高度奖励核

| PPO 迭代 | `track_base_height` 的 `std` |
|---:|---:|
| 0 | 0.080 |
| 1500 | 0.065 |
| 3500 | 0.050 |

收紧还必须满足高度闸门：高度绝对误差小于 `0.05 m` 的环境比例，其 EMA 达到 0.5。
EMA 系数为 0.01。未过闸时即使达到迭代数也停在当前档。

### 开局难度

| PPO 迭代 | 根姿态/速度与关节初速度的包络倍率 |
|---:|---:|
| 0 | 0.0 |
| 650 | 0.2 |
| 2000 | 0.6 |

## 6. 终止条件

| 条件 | 判据 | 是否触发 `is_terminated` |
|---|---|---|
| `time_out` | 满 20 s | 否 |
| `fell_over` | 根刚体相对重力倾角超过 70 度 | 是 |
| `collapsed` | 骨盆相对最低足底的高度小于 `0.35 m` | 是 |

坍塌高度以脚为基准，不会把走下坡或地面绝对高度变化误判为坍塌。阈值低于高度指令下界
`0.50 m`，所以深蹲仍是合法行为。

## 7. Play 配置的覆盖

`play=True` 不是训练配置的原样复制，它会做以下覆盖：

- episode 长度设为近似无限，关闭 Actor 噪声与延时，清空所有课程。
- 删除 `push_robot`，但保留手臂力矩、手臂目标漂移和机身冲量，并直接设到课程末档。
- reset 根状态和关节初速度直接设到末档，`track_base_height.std` 设为 0.05。
- 速度范围改为 `vx [-0.5,1.0]`、`vy [-0.5,0.5]`、`omega [-pi/2,pi/2]`。
- 高度范围改为 `[0.52,0.80] m`。

因此评估 play 结果时，不应把它的指令分布直接当作训练末档分布。

### 奖励与步态

| 结论 | 实测结果 | 当前处理 |
|---|---|---|
| 欠速项只能做弱辅助 | 权重 -0.3 跑 1500 迭代，前向达成率仅 0.04 -> 0.10，历史同期为 0.51；落地峰值 0.23 cm vs 2.45 cm，双支撑 77.5% vs 34.5% | `velocity_shortfall=-0.08`，目标改为指令的 0.5 倍 |

| 打滑必须重罚 | `foot_slip` 从 -0.25 提到 -2.0，并同时放松动作变化、加强腾空奖励后，单脚腾空 0.006 s -> 0.097 s，摔倒率 2.47 -> 0.04 | 保持 -2.0 |
| 固定相位起点会破坏左右对称 | 原设置中 85% 的运动环境右脚先迈；随机后左摆 47%、右摆 41%、双支撑 12% | 每局随机相位起点 |

### 姿态与安全

| 结论 | 实测结果 | 当前处理 |
|---|---|---|
| 对称躯干项不能单独治后仰 | 后仰策略/正常策略的 `body_orientation_l2` 成本比：站立 1.31，前进 0.5 为 0.66，前进 1.0 为 0.25，蹲走为 0.36 | 保留对称项，另加骨盆前后倾项 |
| 后仰必须量骨盆 | 两策略躯干角 +1.4/-1.6 度，骨盆角 -4.9/-9.0 度；腰 pitch 抵消了骨盆差异 | `pelvis_backward_lean` 作用于 `pelvis` |
| 腰部约束不能一次叠加过多 | 腰缩放、动作惩罚和关节约束同时修改后，`body_orientation_l2` 从 -0.0066 恶化到 -0.0200 | 当前删除 `waist_action_rate`，仅缩小 waist roll/pitch 动作范围 |
| 腰 yaw 不能完全无绝对约束 | 无约束版本站立均值 +9.4 度、峰值 20.3 度；消融后达到 +20.8 度 | `waist_deviation` 对 yaw 使用 0.4 系数 |
| 软限位项与直膝目标冲突 | 膝软限位下界 +0.061 rad；膝角 0 时，历史 `joint_pos_limits=-10` 单拍成本约 0.61 | 删除 `joint_pos_limits` |
| 全身自碰撞会误罚手臂扰动 | 5 个场景中，旧传感器的碰撞 100% 含手臂：手臂-躯干 73.1%，手臂-腿 26.1%，双臂 0.9% | 只统计左腿与右腿 |
| 腰关节速度项有效但代价大 | 历史消融 `waist_vel` 后，yaw 误差 2.42 -> 2.87，打滑 0.162 -> 0.177，+1.0 rad/s 转向 6 次摔 3 次 | 主任务未启用，V2 保留 |
| 终止惩罚不能过轻 | `is_terminated=-75` 在第 400 迭代局长 323，历史 -200 对照为 754；坍塌 11.3 vs 2.0 | 当前取 -120 |
| 坍塌阈值 0.32 过低 | 组合实验中改回 0.35 后，第 250 迭代局长 318 -> 429，腾空 0.0095 -> 0.0145 | `collapsed=0.35 m` || 骨盆后仰会直接变成后退偏置 | 见下方“骨盆姿态→后退偏置” | 后仰侧改线性 |
| 平方形式推不动姿态 | 把死区从 4° 收到 3.5° 只把单拍代价从 0.0004 抬到 0.0010，实测骨盆纹丝未动；同位置改线性后值 0.045 | 后仰线性、前倾仍平方 |

**骨盆姿态 → 后退偏置。** 一个策略把骨盆全速度段平铺在后仰死区边上时，机体系 ``vx``
会出现一个恒定后退偏置（指令为 0）。判定它是能力问题还是姿态问题的关键对照：
**同一策略蹲到 h=0.60 就完全不漂**（位移 0.015 m，vx +0.002）——它能停住，只是那个
站姿下停不住。后仰侧改线性后 500 迭代内的变化（干净环境、8 s）：

| 场景 | 骨盆前倾°（改前 → 改后） | 机体 vx（改前 → 改后） |
|---|---|---|
| 站立 h=0.74 | −3.94 → **+1.14** | −0.041 → −0.039 |
| 原地转 +0.8 | −4.90 → **+4.36** | −0.138 → **−0.058** |
| 原地转 −0.8 | −4.28 → **+4.24** | −0.119 → **−0.076** |
| 前进 1.0 | −0.53 → **+5.38** | 0.834 → 0.863 |
| 前进 1.5 | +0.34 → **+6.97** | 1.012 → 1.106 |

六个场景无一例外地从后仰转为前倾，原地转弯的后退偏置同步减半，8 s 位移降 40~70%。
**但站立场景没修好**（vx 基本不变）：站立时腾空率只有 0.005，偏置来源与步态时不同。

还有一条方法论教训：``Metrics/twist/stationary_drift`` 在满档扰动分布下量，被踹飞
产生的位移与偏置无关，整个修复期间它一直在涨。**方向性偏置只能用干净环境的逐指令
扫描来量**，聚合误差看不见——同理，前进变差、后退变好时 ``error_vel_xy`` 纹丝不动。
删除软限位项有已知风险：历史策略在低高度下曾把踝关节压到 -57 度，超过 -50 度硬限位。
若重新加入限位惩罚，应排除膝关节并降低权重。

腰部消融还暴露了训练方差：同一对配置在第 6000 迭代的侧移误差为 0.158/0.023，
第 4500 迭代却为 0.071/0.090。跨配置结论至少应检查两个 checkpoint。

**第 3000 迭代崩塌（后退正常、前进报废）。** 一次 5200 迭代的训练里，`command_vel` 末档
（`vx` 1.0 -> 2.0）与 `command_height` 末档（0.65 -> 0.50）落在**同一迭代**，紧接着是
`height_std` 收紧（3100），而 2600--2800 刚刚把开局难度和手臂扰动抬到满档：

| 迭代 | 2990 | 3010 | 3050 | 5200 |
|---:|---:|---:|---:|---:|
| `Train/mean_reward` | 32.6 | 17.1 | 7.2 | 13.8 |
| `Metrics/twist/error_vel_xy` | 0.99 | 0.79 | 1.26 | 1.65 |
| `Episode_Reward/track_linear_velocity` | 0.97 | 0.58 | 0.40 | 0.31 |

崩塌后 2200 迭代没有恢复。逐检查点扫描 `vx` 指令得到的达成速度（部署链路闭环 8 s）：

| `vx` 指令 | -1.0 | -0.5 | +0.2 | +0.5 | +1.0 | +2.0 |
|---:|---:|---:|---:|---:|---:|---:|
| model_2500（跳档前） | -0.71 | -0.43 | **+0.13** | **+0.42** | **+0.74** | **+1.09** |
| model_3500（跳档后） | -0.76 | -0.51 | **-0.08** | **+0.12** | **+0.17** | **-0.04** |
| 已部署策略（对照） | -0.66 | -0.38 | +0.16 | +0.43 | +0.69 | +0.75 |

后退毫发无损，前进全线归零。不对称的来源不是方向本身，而是量程：后退只开到 -1.2，
全程在指数核捕获域内；前进开到 2.0，上半段落在核的数值平地里，在那一段里“走”相对
“不动”是纯亏损（实测走路净成本约 0.6/拍，而指令 2.0 时跟随奖励的落差只有 0.04）。
策略能从观测里看到指令，于是学成了“大前进指令就冻住”，再由函数逼近浇到小指令上。
骨盆姿态同时从“随速度递增的前倾”塌回“全程贴着 4 度后仰死区”。

对应的三条处置：`vx` 上界收到 1.5 并分两档；核宽在指令超过 0.8 后放宽；三条不抓闸的
课程档位互相错开。

| 接触对超限 | `MJ_MAXCONPAIR=50` 导致 316 迭代出现 52527 条丢接触警告；分辨率 0.05 -> 0.10 且 scale 6 -> 3 后归零 |

| 强度分箱 | 外力峰值 | 手臂力矩峰值 |
|---|---:|---:|
| `[0.0, 0.2)` | 2.75 N | 0.40 Nm |
